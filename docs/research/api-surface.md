# Tailscale API v2: full surface

Research for the `tailscale-admin` skill, written 2026-10-19.

## 1. Source and diff

- **Source:** the OpenAPI 3.1 document at `https://api.tailscale.com/api/v2?outputOpenapiSchema=true` (title "Tailscale API", version v2, one security scheme `bearerAuth`). Downloaded 2026-10-19. It is byte-identical to the snapshot taken earlier that day: **93 operations across 15 tags. Nothing was added, removed or changed.**
- **Stability:** the document says "the API endpoints documented here are stable unless otherwise noted. However, the OpenAPI spec used to generate this documentation is unstable. It may change or break without notice." Three operations carry an **Alpha** badge: `GET` and `POST /organizations/{organization}/tailnets`, and `DELETE /tailnet/{tailnet}`. The docs say "Alpha API endpoints are not considered stable interfaces" (https://tailscale.com/docs/features/tailnets-api).
- **How §3 below is built:** it is generated by `scripts/research/gen-api-surface.mjs` from the spec, plus a research overlay inside that script. Regenerate it whenever the spec changes; this is the seed of the skill's self-audit.

## 2. Conventions that apply to every operation

| Topic | Fact | Source |
|---|---|---|
| Base URL | `https://api.tailscale.com/api/v2` | spec `servers` |
| Auth | `Authorization: Bearer <token>`, or HTTP Basic with the token as username and a blank password | spec `info.description` |
| Errors | Standard HTTP status codes, with a JSON body `{"message": "..."}` | spec `info.description` |
| Pagination | "The Tailscale API does not currently support pagination. All results are returned at once." **Exception:** `GET /organizations/{organization}/tailnets` takes `limit` (1–100) and `cursor` (changelog, 2026-08-18) | spec; https://tailscale.com/changelog |
| `-` tailnet | `-` in a `{tailnet}` path means "the default tailnet of the credential". The official Go client defaults to `-` | archived `publicapi/tailnet.md` (tailscale/tailscale@041733d3d); tailscale-client-go-v2 `client.go` |
| Tailnet ID | Use the **Tailnet ID** from the admin console's General page instead of the old "organization name", which is now shown as "Legacy ID" | https://tailscale.com/changelog (2025-10-16); https://tailscale.com/docs/concepts/tailnet-name |
| Device filters | `GET /tailnet/{t}/devices` accepts `<field>=<value>` for any top-level scalar or list field (`hostname`, `tags`, `isEphemeral`…). Matches are exact, and several filters are combined with AND. **Tested:** `hostname=` returns the exact match | spec parameter `<field>=<value> filters` |
| `fields=all` | Adds `enabledRoutes`, `advertisedRoutes` and `clientConnectivity` to device objects | spec parameter `fields` |
| Rate limits | **Not documented.** A 429 response (`{"message": "too many requests"}`) is defined. No `Retry-After` or `RateLimit-*` headers appeared on any live response. GitHub issue tailscale/tailscale#14328 asks and is still unanswered | spec `components.responses.429`; live test 2026-10-19 |

## 3. Scope resolution summary

The spec's `OAuth Scope:` line covers 64 of the 93 operations. The rest are resolved as follows:

| Operations | Scope | How it was resolved |
|---|---|---|
| DNS nameservers, preferences, searchpaths, split-dns (9) | `dns:read` / `dns` | Trust-credentials scope table: https://tailscale.com/docs/reference/trust-credentials |
| `GET`/`POST /dns/configuration` | **Unknown** (not on the scope table) | **Tested:** GET returns 200 with `all:read`. The write is untested |
| `POST /acl/preview` | `policy_file:read` | Trust-credentials scope table |
| Device invites: create, resend, accept | None. **User-owned API tokens only** | Spec notes on each operation |
| User invites: create | None. **User-owned API tokens only** ("invites require an inviting user") | Spec note |
| User invites: list, get, delete, resend | **Unknown** | **Tested:** list returns 200 (body `null`) with an `all:read` OAuth token |

Write scopes include their read scope: "Write scopes include everything in their read scope" (trust-credentials page).

## 6. Contradictions and surprises

1. **`/acl/validate` returns 200 on failure.** Spec: "An empty response body implies passing validation or tests." A non-empty body is a failure report.
2. **`/services` returns `vipServices`.** The path is `/services`, but the list response key is `vipServices` (spec schema; live test agrees). The Go client still calls the older `/vip-services` path.
3. **Pagination:** the spec says there is none, yet List tailnets has a cursor.
4. **User invites:** the "user-owned keys only" restriction is stated only on *create*. Listing works with an OAuth token (tested).
5. **Scope name spelling:** the trust-credentials page spells `devices_invites` in one column and `device_invites` elsewhere. The spec uses `device_invites`.
6. **`all:write`** appears in the Go client README but is not a documented scope; the documented scopes are `all` and `all:read`.
